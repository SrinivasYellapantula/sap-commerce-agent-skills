# Composable Storefront Impact of SAP Commerce 2211-jdk21.11 to .15

Use this reference as backend-integration context. It does not establish a Composable Storefront package target by itself. Always derive the storefront version from its package files and consult the official Composable Storefront compatibility/update guide for that exact frontend path.

## Scope boundary

- The Angular 19-to-21 migration and Node/pnpm/TypeScript library tables in 2211-jdk21.14 describe SAP Commerce SmartEdit/npm ancillary code. Do not copy those versions into an external Spartacus/Composable Storefront unless the storefront's own official compatibility guidance requires them.
- Analyse custom SmartEdit extensions separately from the customer storefront. If both exist, produce two package/runtime matrices and two build gates.

## Coupled backend changes to assess

- 2211-jdk21.11 authorization code flow: verify the public redirect host through CDN/proxy, backend `authserver.enable.forwarded.header`, registered redirect URIs, cookie scope, and end-to-end login callback. Treat CDN cookie rewriting as an operational dependency outside storefront code.
- Login page placeholders: align `redirectUriHost`, `lang`/`ui_locales`, `ctx`, and any custom `LoginPageUriPlaceholderProvider` parameters with the storefront authorization request. Test validation, encoding, language fallback, local ports, multisite paths, and allowed hosts.
- Wishlist operations in 2211-jdk21.14: scan custom OCC adapters/connectors and callers for `sort`; affected wishlist operations use `sortId`. Confirm the official Storefront API contract before changing generic sort handling.
- Endpoint rollout: verify effective enablement of `searchInWishlists`, `getAllWishlistProductCodes`, `bulkAddWishlistEntries`, `getOrgUnits`, and `setOrgCustomerDefaultOrgUnit` when custom manifest restrictions override SAP defaults. Map disabled endpoints to storefront feature behavior and tests.
- New payment-tokenization and gift-card rollout flags affect storefront scope only when those features are adopted. Classify absent features as `not needed` only with package/config/CMS evidence.
- 2211-jdk21.15 duplicate controller/bean registrations are a backend startup risk. Record storefront smoke tests as blocked until the OCC/resource server starts cleanly; do not propose a frontend workaround.

## SmartEdit-specific evidence

- For custom SmartEdit code crossing 2211-jdk21.14, scan deprecated Fundamental NGX modules/direct imports, Angular NG0100 failures, signals, Node/pnpm/TypeScript/Zone.js, builders, lint/test tooling, and deleted SmartEdit symbols from the target API report.
- For 2211-jdk21.15, consume the target SmartEdit patch set as supplied and verify custom extension compatibility. Do not manually pin SAP-bundled library versions unless the supported customization workflow requires it.
