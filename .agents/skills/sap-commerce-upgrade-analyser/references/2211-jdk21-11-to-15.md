## Update-specific evidence and required scans

### 2211-jdk21.11

- Authorization-code redirects behind a CDN can require `authserver.enable.forwarded.header=true`. This fixes redirect host resolution; it does not rewrite the `JSESSIONID` cookie domain. Record reverse-proxy/CDN cookie rewriting as a separate operational decision.
- `OAuthClientDetails.loginPageUri` supports built-in placeholders `redirectUriHost`, `lang`, and `ctx`, plus custom `LoginPageUriPlaceholderProvider` implementations registered in `loginPagePlaceholderProviderMap` with `mapMergeDirective`. Scan client data, provider beans, allowed hosts, frontend authorization parameters, and validation of custom values.
- Scan custom accelerator `buildcallbacks.xml` for production filters that exclude `wro_addons.xml`; remove only the obsolete exclusion while preserving other custom exclusions.
- Record JGroups JMX exposure, Tomcat, Solr/Netty/gRPC/Hadoop, and security-library changes as configuration/operational applicability items rather than assuming code changes.

### 2211-jdk21.13

- Re-check custom `JDBCInterceptorFactory` implementations and calls to `createJDBCInterceptor(Tenant, String)`. The release fixes a regression introduced in .10. Keep an existing custom override when datasource-aware logging needs it; `jdbc.interceptor.enabled=false` needs no migration solely for this fix.
- Re-run servlet-container and library compatibility checks because Tomcat and Spring Security changed.

### 2211-jdk21.14

- Hibernate 7: scan Data Hub configuration for explicit/version-specific `hibernate.dialect`, references to removed Data Hub Hibernate statistics/JMX wrapper beans, and custom monitoring code. Remove an explicit obsolete dialect where SAP instructs; use Hibernate's standard statistics API if custom code depended on deleted wrappers. Treat `@Temporal` as a recommended `java.time` migration, not an automatic blocker.
- yForms: scan subclasses/overrides of `OrbeonFormController.getFormDefinition` and `headFormDefinition` for the added `HttpServletRequest` parameter. Evaluate the documented CSP `media-src` change only when yForms and the affected media path are used.
- Accelerator checkout: scan custom code derived from `ChinesePaymentMethodCheckoutStepController` for broad `BindingResult.hasErrors()` checks and evaluate the documented field-specific `paymentId` validation.
- Wishlist OCC: scan clients, controllers, adapters, tests, API docs, and monitoring for wishlist operations that pass `sort`; the affected operations use `sortId`.
- Multipart uploads: scan `cmswebservices` and `commercewebservices` custom `web.xml`, listeners, and upload properties. Do not blindly copy property names from a PDF; verify the live child page and target source because similarly named properties have different scopes.
- SmartEdit/npm ancillary: Angular moves from 19 to 21 and related Node, pnpm, TypeScript, Zone.js, Fundamental NGX, webpack, lint, and test packages move together. Treat this as the bundled SmartEdit workspace, not proof of a Composable Storefront package target. Scan custom SmartEdit extensions, deprecated Fundamental modules, NG0100 failures, and signal migration candidates.
- Integration APIs: run target API/JApiCmp scans across `integrationservices`, `odata2services`, `inboundservices`, `outboundsync`, `outboundservices`, `webhookservices`, and `integrationbackoffice`. The release contains many deletions, package moves, constructor/setter removals, and replacements; never reduce this to a single symbol check.
- Charon is deprecated from the .12 preview/.14 line and scheduled by SAP for removal in Q4 2026. Inventory `com.hybris.charon`, `@Http`, `@Control`, `@OAuth`, `HttpClientFactoryBean`, `Charon.from`, RxJava `Observable`, and Charon-specific Spring beans. Classify migration as recommended for .14/.15 unless current SAP documentation makes it mandatory for the requested target; make it required for a target where Charon is removed.
- Charon migration residuals include annotation mapping, URI/property resolution, return types, exception unwrapping, OAuth client registration/filtering, token caching/refresh, retry semantics, concurrency limits, proxy/non-proxy rules, SSL/trust stores, multipart/file arguments, RxJava-to-Reactor callers, and Spring XML factory/filter order. Do not treat a compile-clean interface rewrite as complete.
- Review feature rollout/default endpoint configuration. If custom manifest properties override defaults, decide explicitly whether wishlist endpoints (`searchInWishlists`, `getAllWishlistProductCodes`, `bulkAddWishlistEntries`) and B2B organization endpoints (`getOrgUnits`, `setOrgCustomerDefaultOrgUnit`) remain disabled or become active. Record other .14 feature toggles only when their modules are present.

### 2211-jdk21.15

- Spring Framework 6.2.19 restores duplicate bean-definition retention after a 6.2.0-6.2.18 regression. Scan controllers and other component-scanned classes also declared as explicit XML beans under different names. If mappings overlap, expect startup failure with `IllegalStateException: Ambiguous mapping`; resolve duplicate registration/mapping before deployment.
- Re-check Spring Security, Tomcat, Solr, Netty, Log4j, Jackson, Bouncy Castle, SmartEdit Angular/pnpm, Node/npm ancillary, and yForms/Orbeon deltas through the live library and compatibility tables. Treat exact pins as release evidence, not reusable hardcoded project targets.

## Analysis classification rules

- Classify every item by module presence and repository evidence. Security/library fixes are `required` for adopting the target binary but do not automatically imply custom-code work.
- Separate `platform supplied by target`, `project code/config change`, `deployment/manifest change`, `data/system-update action`, and `verification only`.
- For a direct .10-to-.15 path, include cumulative .11, .13, .14, and .15 evidence plus .12 preview/rollout effects that SAP carries into the target. State explicitly that the public ledger has no ordinary .12 release root in the current table of contents.
- Re-check the latest Solr validity table and Integration Extension Pack compatibility during the actual run; do not freeze validity dates or pack versions in this reference.
